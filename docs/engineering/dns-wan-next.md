# 提案：动态 DNS、可配置地址与高 RTT 起速

状态：**提案，非功能说明、非门禁证据**。本文提出对主计划 §3.2、§6.4、§7.2、§9.4、§9.5 的修订。现有生产门禁不因此豁免。默认 daemon 仍是单活动电路，未上线集群 DNS。

## 可选解析服务

- 同一个 Edge DNS 入口处理内网和公网：签名内网区本地权威应答；公网交给可配置的递归上游。首版是转发器，不自研从根域起步的迭代器。不缓存公网正答或负答；权威记录、副本和有界在途请求不属于应答缓存。保留原 TTL。
- Core 默认不开启。启用且得到策略授权的 Core 自动发布服务宣告；声明绑定网络、身份/代次、授权端点、服务能力、顺序与到期。其他 Core 可转送原声明，不替对端签名。仅 Core 角色不能推导出 DNS 服务权、区写入权或任意地址授权。
- Edge 初始首选当前已连接且健康的授权 Core；备用按 Edge 实测服务 RTT 排序，故障优先切换，同分按稳定节点标识排序，加迟滞避免抖动。第一个连上的 Core 不保证物理最近。无合格服务时内网查询失败关闭，不向公网发；合法 NXDOMAIN/NODATA 不当超时重试。
- Edge 的连接主机名是申报，不是自授权。登记后把 FQDN、永久 NodeID、地址、代次、版本和有效期绑定到可验证记录。拒绝重名覆盖、不以客户端时间裁决；先实现每区单写、多个授权 Core 持久化只读副本与删除墓碑，故障切换走现有新鲜副本，过期副本拒答。换 Core 不换名字。
- 默认仅认证 Overlay 客户能查，并按身份和全局限制并发、响应、带宽及期限；新包进入处理前按现场身份授权。未指定的 LAN 或公网接口不监听，不开放公共递归。

## 上游和地址

- 目标支持 TCP DNS、UDP DNS 和 DoH；用显式上游与独立引导，DoH 使用 HTTPS over TCP 并验证证书名称，禁止隐式 HTTP/3。严格 0-UDP 模式下 UDP 上游不可用；显式启用时由隔离 DNS 服务进程承担，只允许配置的目的端点。数据面 TCP 不变，不默认回落 UDP。应用在隧道内发 UDP/53 不等于承载或 daemon 使用 UDP socket。
- 不锁死 DNS 服务 IP：签名策略可授权 Core 的 Overlay 地址或独立服务地址。可配置网络前缀须由同一 NetworkRoot 签名并检查与物理、LAN、管理路由冲突；地址分配、策略、DNS、路由读取同一真源。先支持验证过的前缀形状，再迁移任意地址池；不能不改 NodeID/地址绑定就宣称任意 CIDR 已支持。

## TCP 高 RTT 与 TUN

- 冷启动首字节、预热后请求起点首秒接收字节、首个接收数据后的第一秒字节是三种指标；窗口不完整须单列。分别测单应用流和多独立应用流，记录真实 RTT、丢包、应用完整性、P99、CPU、内存、队列和活动电路。现有 connect-to-verified-digest 吞吐回归继续独立记录，不改原底线。
- 预热少量已认证独立活动电路，完整业务流固定绑定；先配额后拨号，不并行重放旧密文，不把同一 E2E TLS 电路跨 TCP 条带化。冷启用现有握手和授权时限，不用 0-RTT 放行应用。单流并行分块只在上层显式支持时做验证和重组，不冒充透明单 TCP 提速。
- 借鉴 sing-tun 的有界读槽、现成就绪批次、聚合减少设备 I/O 和能力探测。先验证当前单队列路径的 CPU/有效字节和 syscall，不把其纯转发跑分当 WSS + hop TLS + E2E TLS 的结果。卸载与多队列分别验证，默认关闭；逐包授权、校验和、MTU 和原有失败关闭不放宽。只用当前版本验证，不恢复旧/新 A/B。

## Linux TUN：按 sing-tun 的具体机制推进

参考固定版本：[sing-box 依赖](https://github.com/SagerNet/sing-box/blob/039d829d20c7bfb963dd73113afa9f2d1f080a70/go.mod#L57)、[sing-tun 批读与批写](https://github.com/SagerNet/sing-tun/blob/4486c14ba472e42f62d04e9b7b661690e62c78f8/tun_linux.go#L521-L619)、[Linux 队列和内核能力探测](https://github.com/SagerNet/sing-tun/blob/4486c14ba472e42f62d04e9b7b661690e62c78f8/stack_go_io_linux.go#L48-L125)。参考机制，不复制整套网络栈。

1. **复用并排空。** 已有固定读缓冲和有界就绪批次；测实际每批包数、空读/就绪 syscall、CPU/有效字节，避免再加一个只有 API 名称、没有减少内核调用的“批量”层。
2. **分段与聚合分开。** 首版 TCPv4 软件分段只产生正常 IP 包、补校验和，每一包仍过原授权。现有独立原语限制 64,000 B 输入、64 段和 67,200 B 输出，不配置 TUN、不改变线协议，也尚未证明可接受真实 Linux 输出。设备验证须覆盖普通包、真实聚合包、超限及截断、无卸载退化；GRO 写回只聚合已通过原授权且符合条件的同流包。不得把远端元数据直接交给内核。
3. **先证明减少设备交互，再增队列。** 记录每有效 MiB 的 TUN read/write 数和单队列 CPU，再决定是否需要多队列。单次 TUN write 针对一个普通或聚合帧，不拿 `writev` 把多个独立 IP 包假作一次写入。多队列单独证明同流顺序、队列上界和失败关闭；默认不启用。
4. **分层验收。** 单候选上分开测设备侧成本与真实加密 E2E，报告双向最慢样本、摘要、CPU、队列与丢包。设备侧快不代表多层 TLS 达标，不用设备裸速替代千兆验收。

## 交付顺序与可验收输出

1. 无缓存 TCP 上游组件与不修改门限的接收端首秒测量，各自有边界测试；未接线时不宣称 DNS 或多流可用。
2. 单授权 Core 到 Edge 的真实进程 DNS 线路，验证可信宣告、来源绑定、内外分流、内网不外泄和 TCP/DoH 上游；默认关闭可完整退回无 DNS。
3. 多 Core 验签、名字副本、过期/回滚/分区和延迟备选、签名地址池，另验显式 UDP 例外与无回落。
4. 多活动电路与高 RTT 首秒矩阵；多队列、GSO/GRO 各自保住原授权。千兆仍以严格 pq768 E2E、256 MiB/方向、三轮双向各 >=1000 Mbit/s 且摘要全部相符为准，受损链路回归继续独立验收。
