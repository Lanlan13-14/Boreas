# 组合性能优化：批存储与接收所有权

本批建立在完整成功的诊断 `45190971153` / `24e7d54` 上。
诊断成功不是附件的最终单核千兆验收；旧失败轮仍保留，不挑绿。

## 同批实施、一次统一验证

1. 发送：普通单记录预算内，真实 TUN 将完整 `MAX_MTU + 1` 守卫读取直接写入连接私有的有界待提交区；同样解析/逐包授权，成功才写前缀、推进 used。后续致命失败整批不提交；局部拒绝仍丢弃；不加定时器、不改变预算和 256 KiB TCP 未发高水位。超过生产记录目标的旧 API 调用仍走原路径。
2. WS 接收：复用连接私有载荷 Vec；帧头、长度、掩码、分片、绝对期限、洪泛和 close 规则不变。完整帧读完并通过原检查才发布，短读错误后禁止重试/重投；只发布本帧实际长度。
3. E2E 接收：完整普通包从已有认证明文预取区借用到共享的检查/逐包授权/TUN 写入函数。每次仍只交付一个包，daemon 外层每包停止/撤权检查不变。半帧及 DNS 任何特殊处理均退回原路径。
4. 诊断：默认关闭的记录计数增加批退出原因、包数、有效字节和封帧字节；实际密码参数及记录计数不变。

未做：非阻塞 TLS 状态机、队列扩容、GSO、第二数据线程、辅助密码线程、多 lane、去掉任何安全层。等待状态机必须先有可复现的对向不完整记录阻塞证据。

## 独立证明、统一执行

- 发送保留旧函数；三类 PacketIo（owned/borrowed/inspected），局部丢弃、坏校验、读错误、短写、零写、反复 Interrupted、部分写后超时、flush 失败、预算极值，比对字节/顺序、返回错误、统计、消费个数、连接终态。
- 满包后小包、守卫、旧尾部不发送；实际 TUN 读取指向最终存储且高水分配复用。
- 入站所有截断点、坏前缀、坏源、坏校验、TUN 队列满，与原复制路径逐项比对。
- WS 两角色、短读写、长短帧切换、控制帧和 close 不进入数据流；截断帧不泄漏旧/部分字节，错误后读写终态。
- 真实外层 TLS + WSS + hop pq768 + E2E pq768 双向传输，限制 outer TLS 以上每次读写 257/4096 字节，不使用明文替身。测试相同逐包边界与干净关闭。
- 统一 Actions：默认特性、严格 Clippy、tunnel/daemon 回归、release 真实 A/B、未启计数器的 pre6/candidate 同机配对 C；保留所有证据。
