# Endpoint candidate save: next implementation contract

## Scope and current behavior

This is the next user-facing step after the existing endpoint-only preview: persist a reviewed candidate, **not** install, apply, reload, connect, or mutate the active configuration. The current console flow in [`main.rs`](../../crates/boreas-cli/src/main.rs) reads/validates the source with `Config::read_file(..., NO_RUNTIME)`, changes only `uplinks.primary/backup`, calls `Config::validate`, serializes and reparses a `[uplink]` TOML fragment, then explicitly labels it preview-only (roughly lines 655–750 and 975–1007). [`tui.rs`](../../crates/boreas-cli/src/tui.rs) currently tells users that the candidate can be previewed but not saved and that `SAVE` is not an available action (roughly lines 1094–1118); its reducer already treats confirmation phrases exactly, not as trimmed/case-folded equivalents (tests around 1580–1612).

Reuse the existing validator and endpoint-only serializer; do not create a second policy parser or serialize the full source configuration. `Config::validate` must remain the authority: current identity, security mode/suite, paths, limits, runtime capability checks, and the hard refusal of non-default overlay prefixes all remain intact. `Config::read_file` establishes the existing source-read contract (64 KiB, regular file, final symlink/reparse rejection, Unix descriptor metadata, owner and mode checks); see [`config.rs`](../../crates/boreas-cli/src/config.rs) lines 34–35, 696–746 and [`config/README.md`](../config/README.md) lines 82–96. Save must not read key/root contents or change references to them.

## Minimal file scope

Implementation change should be limited to:

1. `crates/boreas-cli/src/main.rs`: wire the explicit save-candidate action to the validated endpoint fragment and filesystem writer; keep preview behavior intact.
2. `crates/boreas-cli/src/config.rs`: only if a narrowly reusable create-new/no-follow writer or typed error belongs with the current bounded file contract; do not alter validation or source-read policy.
3. `crates/boreas-cli/src/tui.rs`: offer the save action and confirmation/cancel transitions; keep exact phrase matching and do not add a path-entry flow.
4. `crates/boreas-cli` tests colocated with the affected modules. No deployment scripts, manifests, dependencies, installer, daemon, or active-config editing in this slice. Update docs only after implementation/evidence in its own follow-up.

## User-facing API and path contract

Expose a distinct `config-save-candidate` action (and the console wizard action) that takes the already-entered endpoint values, not an arbitrary output path. It returns a clear success/failure result and a display-only destination label. A successful response says **saved as candidate; not applied**. It must not imply validation of reachability or activation. Non-TTY callers must pass an explicit `--confirm SAVE`; absent confirmation fails closed without prompting, and stdin is never read for confirmation. On a TTY, prompt for the exact uppercase line `SAVE`; accept only exact `SAVE` (no trimming, case folding, or prefix match), otherwise cancel without writing. The confirmation names the action and destination label before the user confirms.

Write only under the managed per-user candidate directory:

- Unix default: `$XDG_CONFIG_HOME/boreas/candidates` when `XDG_CONFIG_HOME` is absolute and safe; otherwise `$HOME/.config/boreas/candidates`. Do not interpret a relative override, fall back to the source config's directory, or accept a caller-supplied arbitrary destination. If neither safe location can be established, refuse.
- The app-owned `boreas/candidates` directory and its required parent directories must be real directories, owned by the effective user, and private (Unix mode `0700`, with no group/world access); reject symlink components and unsafe ownership/permissions. Do not chmod or repair an existing unsafe directory. Create missing directories only beneath the verified per-user config root, with restrictive permissions and race-safe directory operations; if the platform cannot enforce the checks, fail closed.
- The final basename is generated by the program, e.g. `uplink-<UTC timestamp>-<random>.toml`; it is never supplied as a path by the caller. Create with exclusive `create_new` semantics, mode `0600` from creation, and no-follow semantics. Never open/truncate/replace an existing file. If collision occurs, generate a fresh name a bounded number of times, then fail.
- Candidate bytes are the already validated endpoint-only TOML fragment (`[uplink]`, primary, optional backup, paths/probe_paths, explanatory not-applied comment) and are bounded by `MAX_CONFIG_BYTES`; use checked bounded writing and flush/sync before reporting success. No full config, key path, trust-anchor path, state path, identity, or unrelated settings are emitted.
- The displayed label is a sanitized basename only, not the absolute path: restrict to a short allowlist such as ASCII alphanumeric plus `-_.`, reject separators/control characters, cap its length, and never echo the raw environment path or OS error path to the screen/JSON. The private directory is app-selected; there is no `--output <arbitrary path>` escape hatch.

Unix implementation should use descriptor-relative directory traversal/open (`openat`-style APIs) with no-follow on each component where available, then create the final file with `O_CREAT|O_EXCL|O_NOFOLLOW|O_CLOEXEC` and `0600`; verify directory/file metadata through descriptors, not a check-then-open pathname sequence. If equivalent race-safe owner/privacy/no-follow semantics cannot be provided on Windows or macOS in this increment, return an explicit unsupported-platform error before creating anything. Do not claim current Windows read-side reparse-point handling or NTFS ACL caveat is sufficient write protection. The deployment support matrix in [`platform-support.md`](platform-support.md) is build/test coverage, not authorization to weaken this contract on a target.

## Required tests (CI only)

- Valid v2 source plus changed endpoints produces exactly one endpoint-only candidate under the managed directory; reparsing the fragment succeeds; active source bytes remain identical; result explicitly reports not applied.
- Exact `SAVE` accepted; lowercase, trailing/leading whitespace, prefix, empty, and cancel rejected; non-TTY without `--confirm SAVE` returns promptly, does not prompt/read stdin, and creates no file; non-TTY with flag follows the same validator and writer.
- Existing destination/collision never changes bytes and never gets truncated; symlink/reparse final target and symlinked directory component fail closed; regular-file-as-parent fails closed.
- Unsafe/missing-owner/non-private directory and unsupported platform refuse without writing; verify Unix mode `0600` file and `0700` managed directories, current-user ownership, bounded output, and no-follow/exclusive behavior.
- Candidate validation still rejects malformed endpoint, identity/node-ID mismatch, changed security/suite, unsupported runtime capability, and non-default `overlay_prefix`; no output leaks key/root/state paths. The save path cannot mutate `identity_key`, `roots`, `state_dir`, source config, or arbitrary system paths.
- Label sanitization rejects path separators, control characters and overlong labels; errors and success output do not reveal absolute paths or unsanitized user/environment values.

All Rust tests/build/format/lint checks are CI-only under the deployment policy in [`platform-support.md`](platform-support.md); do not infer acceptance from a local run or from platform build coverage. No daemon reload/apply test belongs in this slice because there is intentionally no apply behavior.
