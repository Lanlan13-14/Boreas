## Candidate and acceptance

- [ ] Freeze the final full source SHA after integration; record candidate ref, final diff, toolchain, lock SHA-256, backend pin, workflow path, run/attempt, job and step outcomes, runner OS/architecture/CPU and binary SHA-256. Check the actual tested checkout and artifact provenance, not just the workflow badge. Run builds, lint, tests and performance in GitHub Actions only; keep `--locked`, negative cases and thresholds intact.
- [ ] At that SHA collect Quick checks (`ci.yml`), Security (`dependencies.yml`), real Linux TUN (`linux-system.yml`), encrypted runtime (`rust-tls.yml`), five-platform packaging (`platforms.yml`) and both OpenWrt builds (`openwrt.yml`). Push path filters can omit Quick checks/platforms/OpenWrt on docs-only or workflow-only diffs; use their existing dispatch support when authorized. The `rust-tls.yml` mandatory summary at the baseline enforces success of DNS, mesh, multi-active, delayed duplex, gigabit and optional-feature GSO **as a required acceptance profile** on upstream `main` or `work/v111-handoff` push/dispatch; an arbitrary ref or PR does not prove those steps ran.
- [ ] Perform mandatory Linux runtime acceptance on actual TUN with strict pq768: baseline WSS/hop/E2E, failure without fallback, private DNS, four-process mesh routing/failover, 2–4 active circuits, and authenticated offline systemd readiness/rollback. Verify every sample in both directions, with integrity: default delayed profile (200 ms each way / 0.1% loss / 100 Mbit/s shaping, 3 Mbit/s minimum per direction), default no-impairment gigabit (1000 Mbit/s per direction), and separate opt-in TCPv4 GSO (1000 Mbit/s per direction, not a substitute for default). Record raw outputs, not average-only or retry-to-green results.
- [ ] Close the remaining handoff scope with tests on the integrated SHA: healthy lanes continue while a failed lane is replaced with a fresh authenticated session; flow retirement cannot rebind old traffic; trusted dynamic Core discovery and persistent conflict isolation survive restart; required private DNS discovery/replication and bounded TCP DNS/DoH/public forwarding and address migration; broader live revocation and resource cleanup races; authenticated online update authorization. Report anything unimplemented, partial or unverified rather than presenting it as supported. A baseline pass for 2–4 lanes only proves the wired fail-closed whole-group halt on lane loss, not recovery. Later recovery/retirement/directory patches do not establish completion until the final integration is verified.
- [ ] If claiming real Windows/macOS packet devices, collect `native-device.yml` evidence (Wintun, Intel/arm64 utun); if claiming OpenWrt, distinguish official 24.10.0 userland on runner kernel from physical router/kernel/procd evidence. `deploy.yml` shell regressions are separate from its `main`-only, explicit `run_real_install` sandbox job. `performance.yml` and the real-install job validate a successful upstream `main` `rust-tls.yml` artifact; compare source SHA and the workflow/installer checkout before citing results. Physical devices, CDN and long-duration field measurements are not covered by isolated CI. Keep separate evidence for any such claims.

## Packaging, security and publication controls

- [ ] Verify `platforms.yml` outputs: two static musl Linux targets, Windows x86_64, macOS Intel and Apple Silicon; each runs locked native tests and executable smoke, Linux ELF static checks and eight distro/architecture CLI smoke jobs. `package.py` generates archives and provenance; `make_index.py` assembles the five-target bundle and `verify_bundle.py` rechecks it. Preserve the archives, `release-index.json`, `SHA256SUMS`, target provenance, smoke/static reports, run/attempt, artifact digests, actual asset sizes and SHA-256, and exact corresponding source/license material. This path is unsigned, `foundation_only`, without a daemon or TLS backend; integrity checks are not authentication. It uploads Actions artifacts and creates no release/tag.
- [ ] Select functional Linux assets independently from successful same-SHA `rust-tls.yml` and/or `openwrt.yml` runs as appropriate. The x86_64 static pq768 backend artifact and OpenWrt per-architecture binaries are separate from generic archives. Never silently mix source SHAs, substitute a runner-userland test for router support, use a binary from a red acceptance run, or advertise the five-target bundle as an installer. Pending: a reviewed final asset list, release version/build identity decision, hashes/provenance and usable installation/rollback instructions for each advertised asset. The generic version is currently `0.1.0`; do not relabel verified archive bytes or imply `BOREAS_BUILD_TAG` is set by the default workflow.
- [ ] Require all Security jobs on the final SHA: locked exact-Cargo.lock RustSec (warnings denied), reviewed crates/MSRV and registry/GitHub/native OpenSSL review, action pin audit against reviewed inventory and remote tags, dependency-tool and reduced-OpenSSL verifier fixtures. The reviewed backend is pinned to OpenSSL `4.1.1-dev` commit `941390af2ac35f41d2f95bb0bac823dbf0700845` with a reviewed archive SHA-256, not an official `4.1.1` release. Security success for the exact commit+digest does not waive affected `4.1.0` releases or close production gates. Refresh official advisories before any publication decision; green fixtures, pin audits and RustSec do not replace an independent audit.
- [ ] Prepare serious, no-emoji release notes from [the template](../../.github/RELEASE_TEMPLATE.md). Include exact SHA, run/attempt, Linux backend vs. foundation-only targets, security/known gaps, compatibility/migration, asset hashes/source, and offline recovery. Use the [release-note validator](../../tools/release/validate_release_notes.py) in the approved verification process and review substance separately. No final notes or release assets are approved here.
- [ ] Obtain separate authorization before any tag, draft or public prerelease. If authorized in the future, `v0.1.0-pre.4` is development only, not latest/stable. As observed, `release` has the independent read-only discovery manifest `stable:null`, `prerelease:v0.1.0-pre.3`; do not merge that branch into source or move discovery ahead of an actual authorized publication. Discovery is not artifact trust or update authorization. Production promotion is separately fail-closed: manual on protected `main`, reviewed separate exact-candidate ledger, offline dual signatures and pretrusted pinned proof verifier; it never publishes. The production evidence ledger and approved signed promotion bundle are not present in this review.
