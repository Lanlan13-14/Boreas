## Current production changes

1. `262c426`: empty ReadAhead fills once before borrowed first-packet delivery; same-cursor partial completion, bounded interrupts, clean EOF, poison on failed delivery.
2. `8616f9e`: daemon configures after DNS/replica binding; ordinary packets in mixed DNS use the borrowed path; one classifier gives Core DNS, Edge DNS, then host order. DNS handlers keep live authority/transaction checks. ReadAhead owns its Admission byte credit, exhaustion falls back.
3. `13677ca`: CircuitStream hands back the allocation only after consuming its final byte; FrameIo and FrameDecoder have at most one recycled relay body, count actual capacities, and retain 8KiB feed/error atomicity.
4. L3 continuation (`a2f59c8` onward), incremental WS (`85e7134` onward), and the application-phase three-layer TLS queue (`0c40d06` onward) now preserve incomplete input and pending output rather than synchronously reading through to a packet. Activation happens only after authenticated role/DNS binding, on eligible single-lane paths with admitted ReadAhead; handshakes and dedicated replica authenticated EOF keep their existing entry. Each TLS layer owns fixed 8KiB input/output and fixed plaintext read/write buffers, reserved in the existing Admission ledger (96KiB for all three, plus existing 16KiB ReadAhead). A retained write keeps its bytes, address, length and acknowledgement owner across WANT; lower-layer retries retain the original attempted slice endpoint. Incremental WS retains header/mask/body and control budgets. Partial TLS reads, WS messages, session frames, L3 frames and queued output retain absolute deadlines rather than renewing on retry. daemon progresses bounded work, returns on Pending, rechecks policy/status/DNS before continuation, and waits on the actual raw-socket interest set. Mixed Core DNS replies share the existing PacketPath pending-write owner; they cannot replace a pending business write. Close notification drains before ordered circuit close.
