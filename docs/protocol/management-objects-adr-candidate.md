# Management object encoding ADR candidates (not frozen)

This note records decisions necessary for an interoperable typed schema; it does not replace Phase 0 review or freeze the protocol.

1. **Encoding proposal.** Deterministic CBOR subset with consecutive unsigned integer keys per envelope/body map, no floats/tags/simple/negative/text/indefinite forms; shortest arguments; deterministic encoded-key order; duplicate keys forbidden. TBS raw bytes are authoritative. Decoders retain the original byte slice for signature verification; decode/re-encode is never an alternative signature input.
2. **Object identifier self-reference.** Candidate rule: `object_id = SHA-256(tbs_raw_bytes)`. `object_id` is not a field of TBS; carry it externally, recompute from the original raw TBS, and reject mismatch. This avoids a self-hash cycle. Hash function/API remains owned by reviewed crypto/integration code; this module does not compute it.
3. **Signature input.** Candidate input is fixed domain bytes `BOREAS-MGMT-OBJECT\0`, `schema_version:u16be`, `object_type:u8`, `raw_tbs_len:u64be`, then exact raw TBS. No signature, signature length, or key-algorithm guess appears in TBS. Ed25519+ML-DSA AND policy and algorithms belong to crypto layer. The domain/layout need review and independent cross-check before freeze.
4. **ML-DSA parameter identification.** NodeIdentity includes an explicit parameter-set integer (candidate `1=ML-DSA-65`, `2=ML-DSA-87`) next to opaque public-key bytes. Never select algorithm from byte length. Exact key syntax/length and selected suite policy must be settled against the chosen standard/backend and represented by an explicit policy enum.
5. **Extensions.** Candidate extension tuple `[id:uint, critical:uint(0|1), value:bstr]`, sorted by id, duplicate IDs reject, critical must be exactly 0/1. No extension ID is currently recognized, so all unknown critical values reject; unknown noncritical values are preserved byte-for-byte. An extension registry must define semantics and bounds before recognizing an ID.
6. **Duplicated common/body bindings.** Where body repeats net, subject, seq or times, decoder checks exact equality: NodeIdentity net_id/Node(node_id)/identity_generation/not_before/expires; AttachmentLease Node(node_id)/attach_generation/not_before/expires; CoreLsa Core(core_id)/seq; RouteGrant Node(subject)/seq/expires; DirectGrant Node(subject)/expires; StatusSnapshot Network/sequence/issued_at/next_update. Global envelope requires nonempty key ID 1..64, issuer_generation >=1, issued_at < expires. Exact subject identity tagged-array representation is candidate.
7. **Meaning/limits still needing ADR.** `node_id` bit relation and VIP allocation; allowed VIP ranges per role; exact `issuer_key_id` derivation and generation semantics; role-to-object authorization; `issuer_generation` meaning per signer; seq namespaces; scope grammar; Core LSA path type codes and neighbor order; IPv4/IPv6 prefix normalization; endpoint hostname IDNA/case normalization; SNI syntax; revocation sub-schema; exact extension registry; time unit all fields. These are not inferred from CBOR or Rust types.
8. **Evidence before freeze.** For each object type: min/typical/max valid raw fixtures; duplicate/unknown/type/range/cross-net/cross-type/common-body/critical-extension failures; exact TBS and signature-input bytes; two independent implementations (Rust and Python standard library) consuming identical vectors. Crypto tests must separately cover valid/invalid dual-signatures and authorization failures, without inventing cryptography in this crate.
